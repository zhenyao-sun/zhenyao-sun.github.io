# GTD

部署于 `https://zhenyao-sun.github.io/GTD/` 的无构建静态网页，手机优先，直接连接 Todoist API v1。静态文件无需服务端，无外部脚本或样式依赖。

## 使用

1. 在 Todoist 的「设置 → 集成 → 开发者」取得个人 API Token。
2. 在网页首次打开时输入 Token。Token 只保存在当前浏览器的 localStorage；另一个浏览器或手机需单独输入。可在连接设置中清除。
3. 所有未完成任务自动载入；新增、编辑、完成、删除同步到 Todoist。任务数据不写进网站源码或静态文件。

## 已确定的行为

所有任务连续展示，名称、描述、日期和四个维度完整换行显示。日程整行浅蓝，截止整行浅红。编辑用单选下拉菜单，完成用左侧勾选按钮并提供八秒撤销，删除前确认。

排序依次为：日期（从早到晚）、时段、地点、类型、角色，再按创建时间和 ID 保持稳定顺序。准确钟点不参与排序。搜索名称和描述，不改变顺序。

北京时间时段优先顺序：

| 时间 | 顺序 |
| --- | --- |
| 11:30 前 | 早上、任意、中午、下午、晚上 |
| 11:30 至 13:30 前 | 中午、早上、任意、下午、晚上 |
| 13:30 至 17:00 前 | 下午、早上、中午、任意、晚上 |
| 17:00 起 | 晚上、早上、中午、下午、任意 |

时间边界和跨日自动重新排序，时区固定 Asia/Shanghai。地点按钮记住选择；所选地点优先，其次「任意」，再按办公室、良乡家、六里桥、健身房的固定顺序排列剩余地点。选任意时，任意优先，其他地点仍全部显示。

四个维度分别存为 Todoist 标签，每个任务每维恰好一个：

- `角色_`：运动员、数学家、教授、其它。
- `地点_`：办公室、良乡家、六里桥、健身房、任意。
- `时段_`：早上、中午、下午、晚上、任意。
- `类型_`：日程、截止、每日、每周、每月、每年、行动、等待（此顺序也是类型优先级）。

缺少标签自动补其它／任意／任意／行动，缺少日期自动补北京时间今天，并写回 Todoist。保留其他无关标签；旧的 `时间_` 标签转换为 `时段_`。相同维度的多余标签归一为一个有效值。过期日期保持不变。

每日／每周／每月／每年分别对应 `every! day/week/month/year`，以完成日重新计算下一次。其他类型不重复。使用 Sync API 的完整 due 对象保留指定日期，包括过期日期；重复任务完成后由 Todoist 推进同一任务的下一次日期。完成操作使用带 UUID 的 `item_close`，网络超时后重复尝试也不会重复推进日期。撤销重复任务使用 Todoist 的 `item_update_date_complete` 反向操作恢复原日期。

## 文件

- `index.html`、`style.css`：布局及手机编辑面板。
- `app.mjs`：交互、同步、规范化与撤销。
- `api.mjs`：Bearer 鉴权、分页读取、Sync 命令和错误处理。
- `core.mjs`：可独立测试的时间、标签和排序规则。

API 凭证只在请求 Authorization 标头中发送到 `https://api.todoist.com`。没有代理服务、分析追踪、CDN 或 Service Worker。同步失败时保留已有列表或编辑内容并显示错误；不静默丢弃操作，不自动重试写请求。保存使用保留的 Sync 命令 UUID，避免相同提交重试产生重复任务。

本机预览可在仓库根运行 `python3 -m http.server 8765`，访问 `http://localhost:8765/GTD/`。
